# گزارش نهایی محلی اپ‌های بازار آگهی

**تاریخ:** ۲۰۲۶-۱۰-۰۴ — دامنه: پیاده‌سازی Flutter و ساخت debug محلی؛ استقرار اینترنتی انجام نشده است.

## نتیجه و رفتار

اپ آژانس بازار عمومی/همکاری، تنظیمات مستقل انتشار و صندوق گفت‌وگو را دارد. اپ عمومی ورودی، شناسه نصب و فضای توکن مستقل دارد؛ ورود با موبایل و کد موقت نمایش‌داده‌شده از سرور انجام می‌شود و مسیر CRM یا صف آفلاین را اجرا نمی‌کند. هر دو از انتخاب وابسته استان، شهرستان و شهر و نمایش امن آگهی استفاده می‌کنند. اطلاعات قابل نمایش آگهی به محله، مشخصات مجاز، قیمت، تصاویر انتخاب‌شده و تماس آژانس محدود است؛ اطلاعات مالک و نشانی دقیق در مدل آگهی نگهداری نمی‌شود. مقادیر enum مشخصات با برچسب فارسی نمایش داده می‌شوند؛ نوع سازه متن آزاد است.

کارت‌ها قیمت و خلاصه را نشان می‌دهند. فهرست هنگام برگشت برنامه تازه می‌شود؛ جزئیات هر ۳۰ ثانیه و چت هر ۱۵ ثانیه بررسی می‌شود. تاریخچه متن گفت‌وگوی بسته قابل مشاهده است؛ کنترل ارسال متن/عکس و تصویر پیام بسته غیرفعال می‌شوند. با پاسخ ۴۰۱، ۴۰۳ یا ۴۰۴، تاریخچه‌ای که دسترسی آن لغو شده پاک می‌شود. کنترل همکاری برای حساب فاقد مجوز غیرفعال است؛ اجازه قطعی مشاهده، انتشار و عکس در سرور بررسی می‌شود.

## بررسی‌ها

- `flutter analyze --no-pub`: بدون خطا.
- `flutter test --no-pub`: تمام ۶۹ آزمون موفق، پس از اصلاح نمایش قیمت کارت و ثبت observer چرخه برنامه.
- آزمون‌های mock شامل جداسازی ورود عمومی از CRM، حذف فیلد خصوصی، تغییر منطقه وابسته، صفحه خالی در عرض ۳۷۵ و متن بزرگ در تم تیره، ارسال نسخه صفر انتشار اولیه، گفت‌وگوی بسته و لغو دسترسی است.
- هر دو ساخت debug موفق؛ `aapt` شناسه/نسخه/برچسب را تأیید کرد و `apksigner verify` امضا را معتبر دانست. نشانی محلی در `kernel_blob.bin` هر دو APK نیز تأیید شد.
- `adb devices` هیچ دستگاهی نشان نداد؛ نصب، اجرا روی دستگاه، TalkBack، بررسی واقعی landscape و آزمون اتصال کامل به API انجام نشده‌اند. هیچ گوشی فیزیکی نصب یا حذف نشده است.
- آزمون‌های موبایل از پاسخ ساختگی استفاده کردند؛ این کار دیتابیس را تغییر نداده است. موفقیت ساخت و mock به معنی موفقیت ورود به API زنده نیست.

## پیکربندی محلی و ساخت دوباره

هر دو فایل بالا مقدار ثابت زمان ساخت `API_BASE_URL=http://192.168.1.80:8080/api/v1` دارند. این IPv4 شبکه Wi-Fi فعلی و وابسته به DHCP است؛ گوشی باید در همان شبکه و سرویس محلی قابل دسترسی باشد. آماده‌سازی و سلامت سرویس، مهاجرت‌ها و داده مرجع مناطق باید مستقل بررسی شوند. سرور اینترنتی قدیمی این تغییرات را دریافت نکرده است.

از مسیر `D:\app\fandoogh\mobile`:

```powershell
flutter build apk --debug --flavor internal --no-pub --build-name=0.3.0 --build-number=8 --dart-define=API_BASE_URL=http://192.168.1.80:8080/api/v1
flutter build apk --debug --flavor publicInternal --target lib/main_public.dart --no-pub --build-name=0.3.0 --build-number=8 --dart-define=API_BASE_URL=http://192.168.1.80:8080/api/v1
```

برای شبیه‌ساز استاندارد Android روی همین میزبان معمولاً نشانی میزبان `http://10.0.2.2:8080/api/v1` است؛ این مقدار باید با همان `--dart-define` در ساخت جدا تعیین و دسترسی سرویس آزمایش شود. اجازه HTTP فقط در manifest موجود `src/debug` است؛ مجوز HTTP تازه‌ای در main، production یا release افزوده نشده است. حذف define، مقدار HTTPS قدیمی `https://crm.fandooghstudio.ir/api/v1` را انتخاب می‌کند و برای آزمون قابلیت‌های جدید مناسب نیست.
